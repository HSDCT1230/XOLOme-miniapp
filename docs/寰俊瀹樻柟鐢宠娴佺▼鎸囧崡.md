## 二、分步申请流程

### Step 1：注册小程序账号（1个工作日）

```
1. 访问 https://mp.weixin.qq.com/wxopen/waregister
2. 选择「小程序」类型
3. 使用未注册过公众号/小程序的邮箱
4. 填写企业信息
5. 选择「企业」主体类型
6. 填写管理员信息（需微信扫码验证）
7. 支付认证费 ¥300（企业主体必须认证）
8. 等待审核（通常1-3个工作日）
```

**关键决策点**：
- **主体类型**：必须选「企业」，个人主体无法开通微信支付
- **类目选择**：建议选「IT科技 > 智能硬件」或「电商平台 > 电商平台」
- **服务类目**：可能需要额外资质文件，建议提前在类目库查询

### Step 2：完善小程序信息（审核通过后立即）

```
1. 登录 mp.weixin.qq.com
2. 设置 → 基本设置
   - 小程序名称：XOLOme X1 首发预定
   - 小程序头像：上传品牌 Logo
   - 小程序介绍：全息AI伙伴XOLOme X1的首发限定预定通道
3. 开发 → 开发管理
   - 获取 AppID（填到 project.config.json）
   - 获取 AppSecret（后端使用，妥善保管）
   - 添加开发者（团队成员微信号）
   - 配置服务器域名（request/upload/download/websocket）
```

**注意**：如果使用微信云开发，可以跳过服务器域名配置（云开发自带域名）。

### Step 3：开通微信云开发（5分钟）

```
1. 打开微信开发者工具
2. 用 AppID 创建项目
3. 点击工具栏「云开发」按钮
4. 开通云开发环境
5. 记录 envId（环境ID）
6. 在 app.js 中初始化：
   wx.cloud.init({ env: 'your-env-id', traceUser: true })
```

**云开发免费配额**（足够开发测试）：

| 资源 | 免费额度 |
|------|----------|
| 数据库存储 | 2 GB |
| 数据库读 | 50,000次/天 |
| 数据库写 | 30,000次/天 |
| 云函数调用 | 40,000次/天 |
| 云函数资源 | 40,000 GBs/月 |
| 存储容量 | 5 GB |
| CDN流量 | 5 GB/月 |

### Step 4：开通微信支付商户号（3-7个工作日）

这是最耗时也最关键的一步。

```
准备工作：
1. 确认企业已通过微信认证（年审费¥300已付）
2. 准备对公账户信息

申请流程：
1. 小程序后台 → 微信支付 → 开通
2. 填写商户信息：
   - 经营类目：智能设备/智能硬件
   - 客服电话：公司座机
   - 经营场景：小程序
3. 上传资质：
   - 营业执照
   - 法人身份证
   - 对公账户信息
4. 签署协议（电子签章）
5. 等待审核（3-7个工作日）
6. 审核通过后：
   - 获取商户号 mchId
   - 设置 API 密钥（32位密钥，妥善保管）
   - 配置支付回调域名
```

**常见的支付审核问题**：
- ❌ 经营类目与实际业务不符 → 选"智能设备"
- ❌ 小程序未完成基础开发就申请支付 → 建议先开发好核心页面
- ❌ 营业执照信息过期 → 提前检查有效期

### Step 5：申请订阅消息模板（1-3个工作日）

```
小程序后台 → 功能 → 订阅消息 → 选用模板

本小程序需要的模板场景：
1. 订单状态提醒 — 支付成功通知
2. 退款通知 — 退款到账提醒
3. 活动提醒 — 退款窗口即将到期
4. 待办事项提醒 — 宽限期每日提醒
5. 订单发货提醒 — 物流发货通知
6. 卡券到期提醒 — 代金券即将到期

每个模板申请需填写：
- 模板标题（选现有模板）
- 使用场景说明（描述推送时机）
- 示例内容（展示给审核人员看）
```

**建议策略**：
- 一次性提交所有模板，避免多次审核
- 关键词选择参考：
  - 订单号：{{thing1.DATA}}
  - 金额：{{amount2.DATA}}
  - 时间：{{time3.DATA}}
  - 备注：{{thing4.DATA}}

## 三、模拟验证阶段（申请前）

**在申请审核期间，可以并行进行以下工作：**

### 3.1 使用测试号验证（零门槛）

```
1. 下载微信开发者工具
2. 选择「测试号」模式
3. AppID 留空
4. 导入项目代码
5. 所有页面可在模拟器中预览
6. 点击「预览」可扫码用真机查看
```

### 3.2 测试号能力说明

| 功能 | 测试号 | 正式号 |
|------|--------|--------|
| 页面渲染 | ✅ | ✅ |
| 本地存储 | ✅ | ✅ |
| wx.login | ✅（测试code） | ✅ |
| 微信支付 | ❌ | ✅ |
| 订阅消息 | ❌ | ✅ |
| 云开发 | ❌ | ✅ |
| 真机预览 | ✅ | ✅ |

### 3.3 模拟验证清单

请使用 `mock-data.js` 的本地数据层完成以下验证：
- [ ] 所有页面正常渲染
- [ ] 问卷分页填写流畅
- [ ] 创建订单 + 支付意向金 ¥499
- [ ] 补足大定 ¥1,000 → 订单状态正确流转
- [ ] 确认继续购买 → LOCKED
- [ ] 申请退款 → 订单 REFUNDED
- [ ] 使用 fastForward 模拟时间加速 → 验证宽限期流转
- [ ] 使用 runScheduler 触发定时任务 → 验证转代金券
- [ ] 代金券过期逻辑正确

## 四、提交审核前检查清单

### 4.1 技术要求

- [ ] 代码中没有 `mock-data` 的调用（全部替换为云函数）
- [ ] `config.js` 中 `IS_MOCK = false`
- [ ] `project.config.json` 中 `appid` 已填写
- [ ] 云函数已部署
- [ ] 数据库索引已创建
- [ ] 微信支付 `mchId` 和 `apiKey` 已配置
- [ ] 支付回调域名已配置
- [ ] 订阅消息模板ID已填入

### 4.2 审核合规要求（最容易踩坑）

- [ ] **类目匹配**：小程序类目与营业执照经营范围匹配
- [ ] **用户协议**：有明确的用户协议和隐私政策页面（小程序内可访问）
- [ ] **退款规则**：在订单页和预定页**显著位置**标注：
  - ¥499意向金 60天无理由退款
  - 60天到期后7天宽限期
  - 宽限期后转为365天代金券
- [ ] **限购声明**：3000套限量在首页**显著位置**标注
- [ ] **发货时间**：2026年12月31日发货明确标注
- [ ] **无诱导分享**：不使用"分享后获得XX"类文案
- [ ] **无虚拟支付**：仅销售实体商品（硬件），不使用虚拟货币
- [ ] **内容安全**：所有文案通过微信内容安全API审核

### 4.3 常见审核拒绝原因

| 拒绝原因 | 解决方案 |
|----------|----------|
| 类目不匹配 | 选「IT科技 > 智能硬件」 |
| 缺少隐私政策 | 创建独立隐私政策页面 |
| 退款规则不清晰 | 在每个涉及支付的页面上标注 |
| 功能不完整 | 确保所有页面都有内容 |
| 测试账号无法体验 | 提交审核时提供测试账号 |
| 含"预售"敏感词 | 使用"预定"/"首发体验"替代 |
